# MiniMax Flash 独立计划审查

### 阻塞
无。初审提出的事务日志、崩溃恢复、BLE 通知配对、分片、超时与退出边界已有明确契约，可先进入核心实现。

### 重要
1. **BLE 门槛与多设备选择存在措辞冲突**：C 阶段允许多候选时由用户明确选择，但 BLE 门槛写成“发现唯一目标”。应改为“能发现并识别候选目标；单目标环境完成全量读取，多目标环境验证明确选择及错误目标拒绝”，否则多设备环境下无法判定验收是否通过。
2. **Windows 原子替换的持久化语义仍需在实现前落成可测试契约**：目前“带持久化语义的替换操作”尚不够具体。需明确替换 API、同步对象、失败时旧文件/新文件状态，以及目录项持久化是否可保证。该项会影响崩溃点测试设计，但不阻止先实现核心与模拟 transport。
3. **跨重启恢复需补齐恢复事务的冲突校验**：启动恢复当前要求重新读取并预览差异，但应明确以恢复时的 fresh snapshot 校验日志中的设备身份、记录长度和目标槽；若记录已被其他工具修改，是仅预览、拒绝恢复，还是允许用户强制选择。默认应拒绝覆盖，避免恢复本身破坏新配置。

### 后续验收要求
- 旧版并发仅能验收“尽力检测并提示关闭”，不能验收绝对互斥；计划已承认竞态。
- 单槽实机写入、撤销、组合/定时宏及六键实体校正均应在 A–D 通过后执行，不能以模拟结果替代。
- 崩溃恢复必须在各指定崩溃点验证：未尝试槽不列为可能写入、已尝试槽不遗漏、用户确认前零设备写入、日志/备份损坏时安全拒绝。

**结论：可开始。** 上述重要项应在对应 BLE 实机门槛、持久化实现和启动恢复验收前补齐，不构成核心实现启动阻塞。
