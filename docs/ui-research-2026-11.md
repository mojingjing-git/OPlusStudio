# O+ Studio 桌面体验调研与改版

调研日期：2026-11-17。目标为 Windows 上的旧款 O+ 板载配置，不以功能数量或商业宣传断言“最佳”。优先比较成熟产品的可理解性、配置流程、状态反馈和布局；不复制其美术资源或专有代码。

## 旧版实际问题

1. XInput 在线与配置通道就绪是两件事，但旧版将其分散显示，造成“明明已连接却不能编辑”。
2. 主路径被大量工具功能包围：调试地址、协议、电脑键鼠映射与板载设置处于相近层级。
3. 配置页过长；背键编辑、保存、马达和灯光上下堆叠，重要操作会滚出视野。
4. 需要先“加入待写入”，再“保存”，且当前值、表单与草稿之间缺乏足够可见的关系。
5. 宏要求直接编辑 `DPAD_DOWN:120/0` 一类协议风格文本，可读性差。
6. Tk 字号、固定尺寸、嵌套滚动与 Windows DPI 行为未组成统一缩放方案。

## 改版方案与取舍

采用 Qt 6 原生桌面布局，保留已有 BLE/事务后端。Qt 6 默认 Per-Monitor DPI Aware V2，使用设备无关坐标及矢量绘制；依据 [Qt 高 DPI 文档](https://doc.qt.io/qt-6/highdpi.html)。不采用整张位图放大，也不同时叠加手工乘 DPI 与框架缩放。

```
固定侧栏       页面标题                         连接并读取
背键设置       设备 / 固件          游戏输入状态 / 配置状态
手柄设置       操作反馈
实时测试       六键总览                 所选键的编辑器
工具与帮助     M1     M2               当前输出
               LM     RM               按住映射 / 定时宏
明暗主题       LK     RK               输出按键 / 宏步骤
               名称来源                新输出预览与错误
               待保存数量              放弃 / 撤销 / 保存到手柄
```

窗口较窄时，总览和编辑器改为上下排列；底部保存区域始终在页面滚动区之外。任务页单独滚动。真实按钮提供 Tab 焦点和可访问名称；Ctrl+S 保存，Ctrl+R 重新读取。

默认浅色工作区与石墨色侧栏，提供深色主题。颜色用于选中与状态辅助，同时用文字说明待保存和错误；避免纯颜色编码。中文采用 Windows 字体回退，不下载网络字体。背景 `#eef1f5`、面板 `#ffffff`、主文字 `#202938`、次文字 `#59677d`、操作蓝 `#315cd5`、侧栏 `#202b3b`。布局留白用于分组，圆角仅用于面板、控件与当前输出，不用装饰性光晕或营销横幅。

主体文本以 14 个逻辑像素为基准，标题与组标题分层；DPI 缩放交由 Qt。小窗口采用纵向重排；宏行用下拉目标及毫秒数值输入，支持增删及排序。组合键仍支持 `A+B`，不要求用户手写时间分隔符。

编辑即时形成内存草稿；任何输入错误都在编辑区显示，并阻止保存。选择其他背键时保留未完成表单。保存调用已有逐槽事务，先检查新旧记录冲突，再备份、写入和核对；撤销仍使用精确期望值。读取不等于持续占用 BLE，“配置已读取”避免误写成持续连接。

主界面聚焦板载配置与输入测试。诊断、曲线只读数据和第二阶段电脑映射继续通过“经典工具”进入，旧功能可访问。迁移过程中不扩大未知固件的写入范围。

`ui-ux-pro-max` 对硬件配置工具的设计系统检索返回了营销页模式，未采用该页面结构；导航检索多为 Web 通用规则，仅将键盘可达性、状态可见和固定操作区作为通用准则。最终布局依据上述产品证据及 O+ 的具体任务设计。

## 验证

- 105 项自动化测试通过，包括原协议与事务测试、草稿、冲突、宏触发标志保留、异步成功/失败、个人校正、校正窗口关闭后等待恢复等。
- 使用已有真实设备记录进行离屏布局渲染，配置 100%、150%、200% 缩放；1280×840 逻辑窗口分别输出 1280×840、1920×1260、2560×1680 实际像素，保存栏保持在窗口内，无横向滚动溢出。
- 960×680 逻辑窗口验证纵向重排，选背键会滚到编辑器；深色主题另作 200% 渲染及目视检查。
- 这些是模拟缩放检查，不等同于已在多个不同 DPI 的物理显示器之间拖动测试。Qt 的 Per-Monitor V2 声明已加入可执行文件清单。
- 本地参考图与渲染结果保存在 `research/ui-reference`、`reports/ui-0.4.0`，不把第三方截图作为应用资产。
- 最终打包版在本机完成真实界面“读取 → M1 临时改为按住 A → 保存并核对 → 撤销并核对”流程；随后再次独立读取，六个宏槽均与原始基线逐字节一致。证据为 `reports/desktop-0.4.0-roundtrip.json` 与 `reports/desktop-0.4.0-final-restored.json`。
- 打包曾发现构建环境 PATH 中其他工具的 ICU DLL 被错误收集；构建脚本现将 DLL 搜索路径限定为项目 Python 与 Windows 系统目录。清理后重建、检查无外部工具运行库混入，并实测启动成功。
