## 一、阻塞项（Blockers）及合入处理

1. **B1：`ble.rs` 写入长度/回读槽号硬编码与 `transaction.rs` 归一化脱节**
   - 发现：`ble.rs:271, 283-289, 326` 残留 `!identity.verified()`、固定长度 `(9, 17, 25)` 及 `read_spec` 的 `n < 6`；`transaction.rs` 的 `normalize_payload` 写死 16 项改键表展开。
   - 合入处理：`ble.rs::read_spec` 支持 `0..8`；`ble.rs::write` 校验 `SupportTier != ReadOnly` 与协议层安全边界；`transaction.rs` 引入 `normalize_against(key, readback, reference)` 按目标/原记录首字节长度动态归一化全零 `[0]` 改键表。
2. **B2：`ReadOnly` 只读模式与按需读取在 `Identity::parse`、`Session::snapshot`、`commands::view` 与 `App.tsx` 的崩溃点**
   - 发现：6 字节一代身份帧报错断连；非 Gen2 发 `0xB0` 抛错中断；`view()` 与 `App.tsx` 无条件读取 `0..6`、`raw.motors/remapping/lighting` 导致缺省能力设备白屏。
   - 合入处理：`Identity::parse` 兼容 `>=6` 字节记录（非 7 字节归入非 Gen2 `ReadOnly`）；`Session::snapshot` 在非 Gen2 或能力不符时捕获异常生成合法 `ReadOnly` 快照；前后端全部改为按 `support_tier` 与 `capabilities` 判空渲染。
3. **B3：引导识别扩展至 7–8 槽时 `slot + 1` 误用模拟扳机 `LT/RT`**
   - 发现：`7 (LT)`、`8 (RT)` 不在 `XINPUT_GAMEPAD.wButtons` 位掩码中，会导致 7–8 槽识别永久超时；且无条件读取 `remapping` 在 `changekey == 0` 设备上报错。
   - 合入处理：采用 8 个纯数字按键标记池 `[(1, A), (2, B), (3, X), (4, Y), (5, LB), (6, RB), (11, L3), (12, R3)]`，按 `active_slots` 动态映射，仅在存在 `remapping` 记录时检查改键冲突。
4. **B4：恢复中心（`validate_journal` / `recovery_edits`）残留 `!identity.verified()`**
   - 发现：非 `1.37` 的 `Compatible` 设备断电后待恢复日志会被 `pending()` 静默丢弃。
   - 合入处理：改为校验备份快照 `support_tier != ReadOnly`、`effective_generation == 2` 及设备身份/地址严格相等，日志记录数上限提升至 `16`。
5. **B5：跨固件导入 `Hold` 字符串中转报错、`Change::Hold` 强依赖 `remap_keys`、缺每槽步数上下文**
   - 发现：`sequence()` 字符串往返会使 `duration_ms=0` 的 `Hold` 报错；`caps.changekey == 0` 时无 `remap_keys`；`Change::encode` 缺 `slot` 参数。
   - 合入处理：跨布局导入直接在 `Program`/`Step` 层逐位转译掩码；`Change::Hold` 改为校验 `layout.digital`；新增 `encode_for_slot(snapshot, slot)` 校验 `slot_step_limit(slot)`（`1..=47`，默认 `42`）。
6. **B6：Win32 `SendInput` 侧键松开 `mouseData`、滚轮脉冲语义与 `windows-sys` feature 缺失**
   - 发现：缺少 `Win32_UI_Input_KeyboardAndMouse` 与 `Win32_Security`；`MouseX1/X2` 松开时 `mouseData` 必须仍填 `1/2`；滚轮无释放事件且混合步不可 `hold_ms == 0`。
   - 合入处理：补齐 Cargo features 并单测断言 64 位 `size_of::<INPUT>() == 40`；`MouseX1/X2` 按下/松开均带 `XBUTTON1/2`；滚轮仅 `down` 发一次脉冲不入 `pressed_tokens`；仅纯滚轮或纯等待步允许 `hold_ms == 0`。
7. **B7：纯 USB 无蓝牙（`view === null`）场景被空状态拦截，且跨实例存在双重注入风险**
   - 发现：`App.tsx:732` 拦截未读取蓝牙状态进入 `keymap`；未持锁可能与旧版或双开实例双重注入。
   - 合入处理：`App.tsx` 对 `page === "keymap"` 免蓝牙放行，`initial()` 直接加载本地 `KeymapStore`；开启键鼠引擎时检查 `legacy_running()` 并持有独立 `native-keymap.lock` 跨进程锁。
8. **B8：BLE 暂停早退泄漏与 `CloseRequested` 主线程死锁隐患**
   - 发现：`?` 早退会泄漏暂停态；持有 `Mutex` 调 `SendInput` 与主线程 `CloseRequested` 同步可能死锁。
   - 合入处理：使用 RAII `BlePauseGuard` 自动恢复；后台工作线程独占持有 `Engine` 与 `Win32Sink`，共享锁内绝不执行任何 Win32 输入/等待系统调用。

## 二、重要项（I1–I8）与建议项（S1–S4）合入摘要

- **I1（暗号透传说明与独占按钮锁）**：已激活组合键的按钮在按住期间被独占（`claimed`），按住 `M1` 再按正面 `Up` 绝不误触 `M2`；`<20ms` 快点子集键松手补发不丢键；界面明确提示 XInput 原生按键透传边界。
- **I2（全局快捷键隔离与本地保存反馈）**：按键录入及弹窗打开时屏蔽全局 `Ctrl+S`/`Ctrl+R`；在 `keymap` 页无板载草稿按 `Ctrl+S` 给出本地已自动保存提示；侧栏与顶栏动态标明“电脑本地映射 · 需保持后台运行”。
- **I3（中文输入法兼容录入）**：前端统一使用 `KeyboardEvent.code` 映射物理键位（免受输入法 `Process/229` 干扰），支持 `NumEnter` 与 `RWin`。
- **I4（`93/94` 改键源兼容）**：仅在 UI 与 `desired_setting` 禁止将 `SELECT/START` 新设为其他目标（允许设回默认清除），`validate_record` 不拒绝板载历史遗留值。
- **I5（马达通道无损往返）**：`Setting::Motors` 仅修改用户调整且 `caps.motors` 启用的通道字节，未启用及未改动通道保留板载原始字节，消除百分比舍入漂移。
- **I6（未知宏键闭环）**：`Layout::new` 拒绝键码 `0`；`key_code` 支持解析 `KEY_{1..=255}` 实现未知扩展键双向无损往返。
- **I7（`F8` 高位判断与告警可关闭）**：严格判断 `(GetAsyncKeyState(VK_F8) as u16 & 0x8000) != 0`；UIPI 注入受阻提示条支持手动关闭并在重启开关时重置。
- **I8（窄窗口与 150% 字号自适应）**：收紧侧栏间距，采用容器查询折叠与弹性换行，确保 `900×650 @ 150%` 无横向溢出。
- **S1–S4**：支持导入转换旧版 `0.4.0` `profile.json`；阶段 3 基线核对聚焦 `identity`/`capabilities`/`raw` 原有全部记录 100% 一致；修正未连接时底栏指示点样式；完善兼容诊断包字段。
