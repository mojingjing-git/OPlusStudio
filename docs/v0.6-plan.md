# O+ Studio 0.6.0 详细实施计划：致动 O+ 全系通用化与原生键盘宏映射

日期：2026-11-17  
目标版本：`0.6.0`（保留 `0.5.0` 原生版与 `0.4.0` 经典版完整发布包不覆盖）  
实机环境：Windows 10/11，已连接致动 O+（USB XInput `045E:028E` 在线，BLE `致动O+_XXXXXX` `98:B6:ED:XX:XX:XX` 在线，预检基线已保存至 `reports/v0.6-preflight-baseline.json`）。

## 1. 目标、范围与红线边界

### 1.1 核心交付目标
1. **致动 O+ 全系手柄通用化（Universal ZD O+ Compatibility）**
   - 解除 `0.5.0` 对单一固件与固定字节表（`1005:2001` + 固件 `1.37` + 固定 10 字节能力表 + 固定 18 键宏表 + 固定 6 槽）的硬编码死锁。
   - 基于 KeyLinker 第二代协议（`effective_generation == 2`）的 **`0xB0` 动态能力描述符与按键表自描述机制**，动态适配不同批次/型号的致动 O+（青春版、标准正版、卓越版、联名版及不同固件版本，支持 1–8 个背键宏槽、动态宏按键位掩码布局、可选每槽步数上限 `0xB0 kind 6`、动态改键源/目标表 `0xB0 kind 3/7`、动态马达通道数与 RGB 分区数）。
   - 对非第二代协议或未知异常结构设备开放**只读连接与一键导出兼容诊断包**，严禁盲写。
2. **电脑端原生键盘/鼠标宏映射（Native Keyboard & Mouse Macro Engine）**
   - 在 Rust 后端（`oplus-core` + `oplus-device`）实现零 Python 依赖的低延迟键鼠映射与多步顺序宏引擎，并在 React/Tauri 前端新增 **“键盘宏映射”** 工作区。
   - 支持**单键/组合键按住映射**、**多步毫秒级顺序宏**（按下执行一次 / 按住循环 / 按下切换循环）、**语义级按键引用计数**（多规则共用修饰键不提前释放）、**`F8` 全局紧急停止**、**中性帧解锁（Neutral-frame Arming）**，以及**页面内物理键盘按键录入**。
   - 提供**“背键 → 键盘宏”一键板载暗号桥接**：针对 XInput 模式下背键不独立上报的硬件特性，内置无冲突冷门板载组合键预设（支持用户自定义），一键将对应 `Hold` 暗号生成到背键草稿并通过既有安全事务写入手柄，实现按下实体背键即可触发电脑键盘宏。

### 1.2 明确安全与合规红线（必须严格遵守）
- **不做任何反作弊绕过**：仅使用标准用户态 Win32 `SendInput` API（填充合法 `wVk` 与 `MapVirtualKeyW` 转换的硬件扫描码 `wScan` 以兼容常规 DirectInput/Steam 单机游戏），保持 `asInvoker` 清单不强制提权。若目标窗口因管理员权限隔离（UIPI）或反作弊拦截导致 `SendInput` 返回 `0`，**立即优雅放弃本次注入并在界面提示用户**，绝不安装内核驱动、绝不注入其他进程、绝不绕过安全机制。
- **不做高危硬件指令**：继续严禁固件升级（OTA/Bootloader）、传感器/摇杆工厂校准（`0x1D ... 0x10`）、恢复出厂设置（`0x16`）及未验证的全零空槽（`[0]`）覆盖写入；马达尾部字节（自动关机计时等）与灯光未知字节（`data4`/`data5`/`light` 及未声明灯区）严格逐字节原样保留。
- **不破坏既有实机配置**：所有实机验证必须在测试前后与 `reports/v0.6-preflight-baseline.json` 逐字节核对一致，确保用户手柄恢复测试前原状。
- **不静默注入与不残留卡键**：程序启动时键盘宏引擎默认**关闭**；执行任何 BLE 扫描/读取/保存/撤销/识别/恢复期间自动**暂停键鼠引擎并释放所有已按下按键**；手柄断连、切换配置、按下 `F8`、关闭窗口或线程异常退出（`Drop` 守卫）时，必须确保所有已注入键鼠按键发送 `KeyUp` / `ButtonUp`。

## 3. 子系统 A 详细设计：致动 O+ 全系通用化

### 3.1 身份与三级兼容分级（`SupportTier`）
在 `oplus-core::protocol::Identity` 中增加协议有效代际计算（严格对齐 `keylinker.py` `effective_generation`）：
```rust
impl Identity {
    pub fn effective_generation(&self) -> u8 {
        if self.generation == 2 && matches!(self.mode, 0 | 7 | 8) {
            1
        } else {
            self.generation
        }
    }
    pub fn is_verified_137(&self) -> bool {
        self.vid == "1005"
            && self.pid == "2001"
            && self.version_display == "1.37"
            && self.mode == 6
            && self.generation == 2
    }
}
```
在 `Snapshot` 上判定三级支持状态 `SupportTier`：
1. **`Verified`（已实测精确型号）**：`identity.is_verified_137()` 且能力表/宏按键表与实测一致。自动启用实测背键丝印预设 `M1, M2, LM, RM, LK, RK`。
2. **`Compatible`（动态兼容 KeyLinker Gen2）**：
   - 条件：`identity.effective_generation() == 2`，`capabilities` 长度 `>= 10`，`macro_keys`（若 `caps.macros != 0`）非空且无重复、总位宽 `<= 24`，已读取的各项设置记录长度与设备自身声明一致。
   - 允许读写设备实际声明支持的配置项（宏槽、马达、标准改键、RGB），全程受相同备份、冲突校验、回读核对与逆序回滚保护。
   - **预设标签策略**：若 `identity.vid == "1005"`（致动厂商代码）且激活宏槽恰好为 `[0, 1, 2, 3, 4, 5]`，默认提供致动 O+ 六背键丝印 `["M1", "M2", "LM", "RM", "LK", "RK"]`（界面注明“致动 O+ 家族默认名称，可通过引导识别核对”）；其他槽位组合（如 4 槽或 8 槽）按 KeyLinker 标准槽序 `["M1", "M2", "M3", "M4", "M5", "M6", "ML", "MR"]` 取对应激活位名称，个人按蓝牙地址保存的修正始终最高优先。
3. **`ReadOnly`（只读诊断模式）**：
   - 当 `effective_generation() != 2`，或能力描述符/记录结构不符合上述安全约束时触发。
   - **连接不断开**！允许前端查看设备身份、原始十六进制表，并点击“导出设备兼容诊断包”，但后端 `transaction::prepare` 与前端保存按钮均明确拦截任何写入操作。

### 3.2 动态能力查询与按需读取（`protocol.rs` & `ble.rs`）
1. **查询白名单扩展（`protocol::query`）**：
   - 身份与能力查询（连接后即可执行）：
     - `0x91`：空负载（VID/PID/固件版本/代际标志）
     - `0x90`：`payload.len() == 1 && payload[0] < 8`（读取控制器内部名称，如 `致动O+`）
     - `0xB0`：`payload.len() == 2 && payload[0] < 8 && (1..=7).contains(&payload[1])`（新增允许 `kind 6` 每槽宏步数上限、`kind 7` 改键可选目标表）
   - 配置记录读取（当 `effective_generation() == 2` 时执行；若为非 Gen2 只读模式则仅读取身份与 `0xB0` 基础信息，不盲发 `0xB1..0xB7`）：
     - `0xB1 | 0xB2 | 0xB3 | 0xB4 | 0xB6 | 0xB7`：`payload.len() == 1 && payload[0] < 32`
     - `0xB5`：`payload.len() == 2 && payload[0] < 32 && payload[1] < 8`（支持 0..8 全部宏槽索引）
2. **按 `Capabilities` 位掩码按需读取（`Session::snapshot`）**：
   - 解析 `capabilities`（`0xB0, [0, 1]`）：
     - `sticks` (`d[0]`) != 0 时读取 `0xB1`；
     - `triggers` (`d[1]`) != 0 时读取 `0xB2`；
     - `motors` (`d[2]`) != 0 时读取 `0xB3`；
     - `changekey` (`d[5]`) != 0 时读取 `0xB0 kind 3` (`remap_keys`) 及 `0xB6` (`remapping`)；若 `(d[5] & 0x02) != 0`（`D6.bit1`），额外读取 `0xB0 kind 7` 解码为 `decoded.remap_targets`（否则 `remap_targets = remap_keys`）；
     - `lighting` (`d[6]`) != 0 时读取 `0xB7`；
     - `macros` (`d[4]`) != 0 时读取 `0xB0 kind 5` (`macro_keys`)，若 `(d[7] & 0x02) != 0`（`D8.bit1`），额外读取 `0xB0 kind 6` 解码每槽 `u16` 步数上限存入 `decoded.macro_limits`；仅对 `0..8` 中 `(d[4] >> slot) & 1 != 0` 的激活槽读取 `0xB5 [0, slot]`！
   - 尽力读取 `0x90 [0]` 获取 UTF-8 名称（去除控制字符与尾部 `\0`），存入 `decoded.device_name`（若设备超时或返回空，忽略错误不影响快照）。

### 3.3 动态布局、校验与跨固件配置导入（`model.rs` & `transaction.rs`）
1. **`Layout::new(keys)` 未知键码容错**：
   - `18` (`LSTICK_ANALOG`) 与 `19` (`RSTICK_ANALOG`) 占 4 位且空闲值为 `0b1000`；其余任意非零单字节键码均占 1 位（已知键映射标准名，未知扩展键映射为 `KEY_{code}`），总位宽不超过 24 位（`pos <= 24`）。这样新固件即使增加扩展键码，也能无损解析、显示和回写。
2. **每槽宏步数上限计算 `snapshot.slot_step_limit(slot)`**：
   - 若设备提供 `decoded.macro_limits[slot]` 且非 0，则取 `limit.clamp(1, 47)`（47 步 = 238 字节，确保不超过 KeyLinker 4-bit chunk 索引上限 240 字节）；否则默认 `42`（与实测 1.37 完全一致）。
   - `ble.rs::write` 对 `macro_{slot}` 允许槽号 `0..8`（须在激活槽内），长度上限放宽至 `238` 字节（`8..=238` 且 `(len - 3) % 5 == 0`）。
3. **设置项动态长度与未知字节保护**：
   - `motors`：要求 `original.len() >= 5`（即 `declared >= 4`），写入长度必须严格等于 `original.len()`；仅允许修改 `(caps.motors & (1 << ch)) != 0` 的通道字节 `1 + ch`，未启用通道及 `original[5..]` 尾部全部字节必须与 `original` 完全相等。
   - `remapping`：`sources = snapshot.keys("remap_keys")?`，`targets = snapshot.remap_targets()?`。`normalize_payload_for(snapshot, "remapping", p)` 在 `p == [0]` 时展开为 `vec![sources.len() as u8]` 加 `sources.len()` 个 `0`（在 16 键设备上仍为 `[16, 0..0]` 共 17 字节，100% 兼容现有黄金测试！）。禁止将 `93 (SELECT)` 或 `94 (START)` 设为重映射来源（固件静默忽略该来源，但允许作为重映射目标）。
   - `lighting`：要求 `original.len() >= 7 && (original.len() - 1) % 6 == 0`，写入长度严格等于 `original.len()`；仅允许修改 `zone < (original.len() - 1) / 6` 且 `(caps.lighting & (1 << zone)) != 0 && zone < 4` 的前 3 个 RGB 字节，其余 `data4`、`data5`、`light` 和不支持灯区字节必须与 `original` 逐字节相同。
4. **跨固件背键配置导入（`import_profile`）**：
   - 支持导入任意槽数（`1..=8`）的 `oplus-rear-v1` 或完整 `Snapshot` JSON：
     - 若导入文件的 `macro_keys` 与当前手柄完全一致：保持原有 `Change::Record` 精确字节导入。
     - 若导入文件的 `macro_keys` 与当前手柄顺序不同（例如跨 O+ 固件版本分享配置）：用源文件自带的 `Layout::new(&src_macro_keys)` 将每槽解码为按键名与时序，再用目标手柄的 `Snapshot` 重新编码并校验步数上限！若某槽使用了目标手柄不支持的按键，则返回明确中文错误且不部分修改草稿（All-or-Nothing）。

## 4. 子系统 B 详细设计：原生键盘宏映射引擎

### 4.1 纯核心状态机（`oplus-core::keymap`）
所有键鼠映射规则、匹配逻辑和宏调度器放在纯无 I/O 的 `oplus-core::keymap` 中，通过 `OutputSink` trait 抽象输出，以便在无硬件环境下做 100% 确定性单测。

1. **手柄输入语义集（`PadButton`）**：
   - 数字键：`A, B, X, Y, LB, RB, Back, Start, LS, RS, Up, Down, Left, Right`
   - 模拟量转数字触发：`LT, RT`（默认阈值 `> 64`，可配 `10..=240`），左右摇杆八向阈值 `LXNeg, LXPos, LYNeg, LYPos, RXNeg, RXPos, RYNeg, RYPos`（默认死区 `> 16000`，可配 `4000..=30000`）。
2. **输出键鼠词汇表（`OutputToken`）**：
   - 字母 `A`–`Z`、数字 `Key0`–`Key9`、功能键 `F1`–`F12`（**编译期与校验期双重禁止 `F8`**，保留给全局急停）。
   - 修饰键：`LShift, RShift, LCtrl, RCtrl, LAlt, RAlt, LWin`（兼容旧别名 `Shift -> LShift`, `Ctrl -> LCtrl`, `Alt -> LAlt`）。
   - 编辑与导航：`Space, Enter, Escape, Tab, Backspace, CapsLock, Insert, Delete, Home, End, PageUp, PageDown, Up, Down, Left, Right`。
   - 符号与小键盘：`Grave, Minus, Equals, LeftBracket, RightBracket, Backslash, Semicolon, Apostrophe, Comma, Period, Slash`，`Num0`–`Num9, NumMultiply, NumAdd, NumSubtract, NumDecimal, NumDivide`。
   - 鼠标：`MouseLeft, MouseRight, MouseMiddle, MouseX1, MouseX2, WheelUp, WheelDown`。
3. **规则与板载暗号桥接模型（`KeymapProfile` & `KeymapRule`）**：
   - `KeymapStore`（持久化于 `%LOCALAPPDATA%\OPlusStudio\keymap-profiles.json`）：
     - `schema: 1`, `active_profile_id: String`, `controller_slot: Option<u8>` (`None` 表示自动取第一个在线 XInput 槽位 `0..3`), `trigger_threshold: u8`, `stick_deadzone: i16`, `profiles: Vec<KeymapProfile>`。
     - **注意**：`enabled` 状态**不写入磁盘为 true**，每次启动应用固定为 `false`。
   - `KeymapRule`：
     - `id: String`, `name: String`, `enabled: bool`
     - `rear_slot: Option<u8>`（若关联实体背键槽 `0..7`，用于 UI 展示与板载暗号同步检查）
     - `trigger: Vec<PadButton>`（1–4 个同时按下的手柄输入，内部规范化排序去重；同一 `KeymapProfile` 内不允许两条启用的规则拥有完全相同的 `trigger` 集合）
     - `action: KeymapAction`：
       - `Hold { keys: Vec<OutputToken> }`（1–6 个键鼠按键，按下按顺序发 Down，松开按逆序发 Up）
       - `Macro { steps: Vec<KbStep>, trigger_mode: KbTriggerMode, loop_ms: u32 }`
         - `KbStep { keys: Vec<OutputToken>, hold_ms: u32, gap_ms: u32 }`（`keys` 为空代表纯等待；非空步 `hold_ms` 为 `1..=30000`（滚轮步允许 `0..=30000`），`gap_ms` 为 `0..=30000`；单宏最多 64 步）
         - `KbTriggerMode`：`Once`（按下执行一次）、`HoldLoop`（按住循环，松开立即停止并释放）、`ToggleLoop`（按下启动循环，再次按下同一触发组合停止并释放）
   - **默认背键板载暗号表（`bridge_preset(slot: u8)`）**：
     - 槽 0 (`M1`): `Back + LS + RS` ↔ 板载 `Change::Hold { keys: [93, 11, 12] }`
     - 槽 1 (`M2`): `Back + LS + Up` ↔ 板载 `Change::Hold { keys: [93, 11, 14] }`
     - 槽 2 (`LM`): `Back + LS + Down` ↔ 板载 `Change::Hold { keys: [93, 11, 13] }`
     - 槽 3 (`RM`): `Back + LS + Left` ↔ 板载 `Change::Hold { keys: [93, 11, 16] }`
     - 槽 4 (`LK`): `Back + LS + Right` ↔ 板载 `Change::Hold { keys: [93, 11, 15] }`
     - 槽 5 (`RK`): `Back + RS + Up` ↔ 板载 `Change::Hold { keys: [93, 12, 14] }`
     - 槽 6 (`ML`): `Back + RS + Down` ↔ 板载 `Change::Hold { keys: [93, 12, 13] }`
     - 槽 7 (`MR`): `Back + RS + Left` ↔ 板载 `Change::Hold { keys: [93, 12, 16] }`
     - 提供辅助函数 `check_bridge_sync(snapshot, staged_changes, slot, trigger)`：精确判断当前背键板载配置（或待保存草稿）是否已与该规则的暗号一致，并支持一键生成对应的 `Change::Hold`（自动过滤目标设备 `remap_keys` 支持性）。
4. **组合键无串扰匹配器（Chord Matcher & Subset Suppression）**：
   - 启用规则按 `trigger.len()` 降序排列。
   - **长组合优先占用**：当一帧输入满足高阶组合（如 `Back + LS + Up`）时，该组合的所有组成键被标记为 `claimed`，任何包含其子集的低阶规则（如单绑 `Back` 或 `LS`）在该组合按住期间及**松开过渡期**（直到该高阶组合的所有组成键全部松开前）均被抑制（`latched_chord_buttons` 锁存机制），防止松手先后差几毫秒误触单键规则！
   - **前缀防抖窗口（仅按需启用）**：若当前激活的规则中不存在共享按键的超集规则（例如用户只绑了 3 键背键暗号），匹配延迟为 **0 ms**；仅当某低阶规则 `R_sub` 是另一条已启用高阶规则 `R_sup` 的真子集时，`R_sub` 初次按下等待 `20 ms` 确认未升级为 `R_sup` 后再触发。
5. **引用计数输出层（`RefTracker`）**：
   - 按 `(owner_id, OutputToken)` 追踪持有关系：仅当某键全局持有者数从 `0 -> 1` 时发 `KeyDown`，从 `1 -> 0` 时发 `KeyUp`。
   - `release_all()` 先释放普通键与鼠标按键，最后释放修饰键（`Shift/Ctrl/Alt/Win`），避免残留修饰态触发系统快捷键。

### 4.2 Windows 后台执行线程与 `SendInput`（`oplus-device::macro_runner`）
1. **独立后台线程与零空闲开销**：
   - `MacroRunner` 内部维护专用 OS 线程与 `Condvar` 唤醒机制。
   - 当 `enabled == false` 或 `paused_reason.is_some()`（如 BLE 操作中、前端正在录入按键中）时，线程在 `Condvar::wait` 上挂起，**CPU 占用为 0%，不轮询 XInput，不调用 `GetAsyncKeyState` 或 `SendInput`**。
   - 启用运行时，在 Windows 10/11 上优先使用 `CreateWaitableTimerExW(null, null, CREATE_WAITABLE_TIMER_HIGH_RESOLUTION, TIMER_ALL_ACCESS)` 实现 `2 ms` 高精度定时唤醒（无需 `timeBeginPeriod(1)` 污染系统全局时钟；若 API 不可用则自动回退 `thread::sleep(2ms)`）。
2. **`SendInput` 注入与失败即弃策略**：
   - 键盘事件同时填写 `wVk` 与 `wScan = MapVirtualKeyW(vk, MAPVK_VK_TO_VSC)`；方向键、`Insert/Delete/Home/End/PageUp/PageDown`、`RAlt/RCtrl`、`LWin`、`NumDivide` 设置 `KEYEVENTF_EXTENDEDKEY`。
   - 检查 `SendInput` 返回值：若返回 `0`（被 UIPI 高权限窗口或反作弊拦截），**不做任何重试或绕过**，累加 `blocked_count` 并更新状态快照中的 `injection_warning`（前端顶部实时显示黄色提示条：“目标窗口拒绝模拟输入（可能为管理员权限或反作弊保护），已放弃注入”）。
3. **全方位防卡键守卫（`Drop` + 生命周期联动）**：
   - 线程局部变量 `Win32Sink` 实现 `Drop`：无论线程正常停止、窗口关闭还是发生 panic 栈展开，`Drop::drop` 都会遍历 `pressed_tokens` 发出全部 `KeyUp` / `MouseUp`。
   - `commands.rs` 中：
     - 任何 BLE 请求开始前调用 `runner.set_ble_busy(true)`（同步等待当前 tick 释放所有已按下按键后才进入 BLE 连接）；请求结束后 `runner.set_ble_busy(false)`（恢复后自动要求中性帧解锁）。
     - 前端进入“按键录入弹窗”时调用 `set_recording_pause(true)`，退出时 `set_recording_pause(false)`，杜绝自激录入循环。
     - `main.rs` 的 `WindowEvent::CloseRequested` 首先调用 `runner.shutdown()` 立即停止键鼠输出并释放按键，若此时无 BLE 任务则直接退出，若有 BLE 恢复任务则等待 BLE 恢复完成后退出。

## 6. 独立复审增补契约（B1–B8 & I1–I8 强制执行项）

经独立架构复审（详见 `docs/v0.6-plan-review.md`），实施时必须逐条落实以下强制修正：

1. **B1（传输层与事务层去硬编码闭环）**：
   - `ble.rs::read_spec` 允许 `macro_0..macro_7`（`n < 8`）；`ble.rs::write` 移除 `!identity.verified()` 与固定 `(9, 17, 25)` 长度锁，改为校验会话 `SupportTier != ReadOnly` 及协议分片安全边界（`motors: 5..=240`、`remapping: 2..=240`、`lighting: 7..=240 && (len-1)%6==0`、`macro_{0..7}: 8..=238 && (len-3)%5==0` 且 `slot` 属于激活槽）。
   - `transaction.rs` 新增 `normalize_against(key, readback, reference)`：当 `key == "remapping" && readback == [0] && !reference.is_empty()` 时，按 `reference[0]` 动态展开为全零表，确保非 16 键手柄在 `apply` 与 `rollback` 时回读比对精确一致。
2. **B2（`ReadOnly` 降级不断连与前后端空安全）**：
   - `Identity::parse` 兼容 `declared >= 6` 的身份帧（非 7 字节记录将 `mode/generation/sensor` 置 `0`，自然归入 `ReadOnly`）。
   - `Session::snapshot` 在 `effective_generation != 2` 或 `0xB0` 查询/解析异常时不抛错断连，而是将原因记入 `snapshot.errors` 并返回 `SupportTier::ReadOnly` 快照。
   - `commands::view` 与 `App.tsx` 全面对 `raw.motors`、`raw.remapping`、`raw.lighting`、`decoded.macro_keys`、`decoded.remap_keys` 做判空与按需渲染，`ReadOnly` 下主工作区展示设备身份与“导出设备兼容诊断包”按钮，杜绝白屏。
3. **B3（7–8 槽引导识别数字按键池）**：
   - `input::identify` 弃用 `slot + 1`（避免槽 6/7 撞上模拟扳机 `7=LT / 8=RT`），改用 8 个纯数字 XInput 标记池 `[(1, 0x1000), (2, 0x2000), (3, 0x4000), (4, 0x8000), (5, 0x0100), (6, 0x0200), (11, 0x0040), (12, 0x0080)]`，按 `active_slots` 动态分配，且仅当存在 `remapping` 记录时检查标准改键冲突。
4. **B4（恢复中心跨固件兼容）**：
   - `validate_journal` 与 `recovery_edits` 移除 `identity.verified()` 硬编码，改为校验备份快照 `support_tier != ReadOnly`、`effective_generation == 2` 且 `current.identity == j.identity && current.address == j.address`；记录数上限扩至 `16`。
5. **B5（掩码级跨布局导入、无改键表 `Hold` 编码与每槽步数上限）**：
   - 跨 `macro_keys` 导入直接在 `Program`/`Step` 层逐位转译掩码（不经字符串 `sequence()` 中转，完美保留 `duration_ms == 0` 的 `Hold` 映射）；`Change::Hold` 直接校验 `layout.digital` 而非 `remap_keys`；新增 `Change::encode_for_slot(snapshot, slot)` 按 `snapshot.slot_step_limit(slot)` 校验每槽步数上限。
6. **B6（`windows-sys` 特性、`MouseX1/X2` 松开参数与滚轮脉冲规则）**：
   - `oplus-device/Cargo.toml` 启用 `"Win32_UI_Input_KeyboardAndMouse"` 与 `"Win32_Security"`，单测断言 64 位 `size_of::<INPUT>() == 40`。
   - `MouseX1`/`MouseX2` 在按下与松开时均填写 `mouseData = 1 / 2`；`WheelUp`/`WheelDown` 仅在按下阶段发送一次脉冲（`120` / `-120i32 as u32`），不加入 `pressed_tokens`；仅纯滚轮或纯等待步允许 `hold_ms == 0`。
7. **B7（纯 USB 免蓝牙直用 `KeymapPage` 与双开防重锁）**：
   - `App.tsx` 空状态门禁放行 `page === "keymap"`；`initial()` 启动即加载返回 `KeymapStore`；未连接蓝牙（`view === null`）时可正常开启键鼠引擎、管理方案、绑定普通键及默认 6 背键暗号。
   - 开启 `MacroRunner` 时执行 `legacy_running()` 检查并持有独立 `native-keymap.lock` 文件锁，防止多实例双重注入。
8. **B8（RAII 暂停守卫与无锁 Win32 I/O）**：
   - BLE 操作使用 `BlePauseGuard`（`Drop` 自动恢复 `set_ble_busy(false)`）；按键录入弹窗用 `useEffect` cleanup 保底恢复 `set_recording_pause(false)`。
   - `MacroRunner` 工作线程独占持有 `Engine` 与 `Win32Sink`，绝不在持有共享 `Mutex` 期间调用 `SendInput`、`XInputGetState` 或等待函数，彻底消除与主线程 `CloseRequested` 的死锁可能。
9. **I1–I8 & S1–S4 交互与精度细则**：
   - 已激活组合键独占其组成按钮（按住 `M1` 叠加正面按键不串触发 `M2`）；`<20ms` 快速点按子集键松手时立即补发不丢键；界面清晰提示 XInput 原生按键透传物理边界。
   - 录入按键使用 `KeyboardEvent.code`（兼容中文输入法，支持 `NumEnter` 与 `RWin`），录入及弹窗期间屏蔽全局 `Ctrl+S`/`Ctrl+R`；在 `keymap` 页无板载草稿按 `Ctrl+S` 提示本地已自动保存；侧栏与顶栏动态标明“电脑本地映射 · 需保持后台运行”。
   - `SELECT(93)/START(94)` 仅在 UI 与 `desired_setting` 禁止新设为非零改键目标（允许还原默认），`validate_record` 兼容板载历史值；马达按实际修改通道更新，避免百分比舍入改动未触碰/未启用通道；`key_code` 闭环解析 `KEY_{1..=255}`；`GetAsyncKeyState(VK_F8)` 严格只判 `0x8000` 高位，UIPI 告警可手动关闭；兼容导入 `0.4.0` 的 `profile.json`；确保 `900×650 @ 150%` 零横向溢出。
