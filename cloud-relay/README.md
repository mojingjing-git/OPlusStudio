# 免登录反馈：公开字段与发布顺序

- GitHub Issue 公开显示用户手动填写的标题、描述，以及反馈类型、平台、应用版本、回执和提交时间。用户选填的兼容摘要只包含有效的 VID/PID、固件版本和支持分级；不公开联系方式字段、设备地址、设备名称、原始记录或原始报错。
- 旧版客户端可能在描述中预填以 `[最近提示]` 开头的多行错误。无法可靠地区分错误与用户追加的正文，所以 Worker 不发布这整段描述；单独填写的标题仍可保留。老队列从 Worker 拉取时也使用同一规则。
- 界面请勿承诺对用户手动输入的正文做隐私过滤。独立的本地诊断导出功能不变，不要把完整包贴到公开 Issue。
- 本地回归：`node --test cloud-relay/worker.test.mjs`，从仓库根目录执行。测试使用内存 KV 和模拟 GitHub 请求，不需要任何令牌或网络。网页侧用 `npm run test:web`、`npm run build`（在 `native/ui`）。
- 发布：先部署新版 Worker，确认其即时转发和队列返回都经过过滤，再更新定时工作流和前端。新版工作流拒绝没有公开载荷版本标记的旧响应，不会将其确认出队；新版 Worker 的队列格式仍兼容旧工作流。若必须回退到旧 Worker，先暂停公开转发，避免重新暴露旧字段。补丁不会修改已经发布的 Issue 或追溯删除已有 KV 数据。
